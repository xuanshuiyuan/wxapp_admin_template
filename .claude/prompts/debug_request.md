# prompts/debug_request.md — 排障请求提示词

> **用途**：调用 `debugger` 时的提示词片段。
> **核心原则**：**现象越具体，根因越准**。信息不足时宁可停下问，也不要让 AI 猜。

---

## 1. 万能排障模板

```
【现象】<端：mp/h5/app> / <环境：dev/prod> / <操作路径> / <期望> / <实际> / <报错原文>

【类型】bugfix
【要求】先给根因报告（含 file:line 证据），暂不改代码
【验收】根因收敛到一处；已排除的假设列表；无法本地验证的如实标「未确证」
```

---

## 2. 按现象类型的实例

### 2.1 有报错

```
【现象】微信小程序真机，production 环境。
        进首页后控制台报：Im Invalid Request!
        期望：正常返回。
        实际：所有接口都报这个错。

【要求】先给根因（要证据），暂不改代码。

提示：这个错通常是 edition（全局协商头）传了后端未登记的值。
      但请自行验证，不要直接采信我的猜测。
```

### 2.2 行为异常无报错（最难的一类）

```
【现象】登录页点「去绑定手机号」后返回，绑定态仍显示"未绑定"。
        微信小程序真机，production。无报错。
        期望：绑定后返回显示"已绑定"。

【要求】
1. 先给根因（file:line 证据）
2. 列出已排除的假设
3. 注意：admin-home 的 bound 是三态（null=未查到 / false=未绑 / true=已绑），
   会不会是 onShow 时序问题？
4. 仍然：请自行验证，不要采信我的猜测
```

### 2.3 偶现问题

```
【现象】偶现（约 1/10 次）：H5 端连续发两个请求，第二个签名被后端拒。
        无固定复现路径。

【要求】
1. 先查 .claude/memory/bug_history.md（可能已踩过）
2. 给候选根因 + 每条的证伪方法
3. 若无法本地复现，明确说「本环境未复现」并给真机验证步骤
4. ⚠️ 不要为了给结论而假装确定
```

### 2.4 「改了没生效」

```
【现象】改了 src/config/app.js 的 source 值，重新编译后真机上仍是旧值。

【要求】根因 + 证据。
提示：本项目构建产物的「目录由 dev/build 决定，环境由 --mode 决定，两轴正交」
      （见 .claude/QUICK_START.md §6.1），会不会是产物环境搞混了？
      请验证，别直接采信。
```

### 2.5 环境口径问题（本项目高频）

```
【现象】上传到微信的包，接口指向 localhost:15200。

【要求】
1. 根因（不是"忘了跑 build"，要具体到哪一步导致的）
2. 给出预防措施（这次不只是一次性修复）
3. 检查 .claude/memory/bug_history.md 的 BUG-005 是否已记录同类问题
```

---

## 3. 要求 debugger 区分「已证实 / 待验证」

本项目大量问题**只在真机出现**（MP 端样式隔离、`env()` 兼容、签名、弹层 flex）。
这些**无法本地确证**，必须如实标注。

```
【要求】结论里严格区分：
- 「已证实」：有代码/日志/复现支撑
- 「待验证假设」：只有推理，标明「需真机验证」

⚠️ 本项目有很多这类未确证项（见 .claude/memory/known_issues.md 的 🟡 标记）。
   如果你查不出确定根因，说"未确证"是正确回答，不是失败。
```

---

## 4. 要求给「已排除的假设」

**这个要求能显著提高根因质量** —— 它逼 debugger 真正去验证，而不是列出所有可能性。

```
【要求】
1. 根因（一处，一句话）
2. 证据链（file:line 或命令输出）
3. ★「已排除的假设」表：假设 | 排除依据
   —— 这部分必须有，它证明你真去验证了，而不只是列可能性
4. 待验证假设（无法本地验证的）
```

---

## 5. 修复阶段的提示词

**debugger 默认只给根因不给代码**。要修，明确说：

```
根因确认了，按你的最小修复方案改。
要求：
- 只改最小范围，不顺手重构、不改风格、不动不相关文件
- 不碰 src/uni_modules/
- 给出精确 diff + 影响范围 + 回滚方式
- 改完提示我补 memory/bug_history.md 回归条目；若属真重要变更，在 commit message 写一行（见 §11.1）
```

---

## 6. 反模式

| ❌ | 为什么差 |
|---|---|
| 「首页有 bug，修一下」 | 无现象、无端、无环境，只能猜 |
| 「应该是 xxx 的问题，你确认一下」 | 引导 AI 确认既有假设（确认偏误） |
| 「随便看看哪里有问题」 | 无边界扫描，必然发散 |
| 「先修了再说，根因回头找」 | 会修成症状，掩盖真问题 |
| 「加个 try/catch 先别报错」 | 掩盖而非修复（`debugger` 会拒绝） |
| 「加个延时应该就好了」 | 同上，且不同端表现不同 |

## 7. 本项目高频根因速查（可给 debugger 当起手提示）

来自 `.claude/workflows/bugfix.yaml`：

| 排名 | 根因类型 | 取证命令 |
|---|---|---|
| 1 | 环境口径搞混 | `grep -rn "localhost:15200" dist/` |
| 2 | `options` 漏传（`authRetry` / `guard`） | `grep -rn "authRetry\|guard:" src/` |
| 3 | 端差异漏出（`#ifdef` 在页面里） | `grep -rn "#ifdef" src/pages src/components` |
| 4 | 绕过存储层导致真相源分裂 | `grep -rn "getStorageSync" src/ \| grep -v services/storage.js` |
| 5 | `pages.json` 未登记 / `TAB_PAGES` 未同步 | 读 `src/pages.json` 与 `src/services/route.js` |
| 6 | 类名撞 ColorUI | `grep -n "^\." src/common/css/main.css` |
| 7 | `edition` 改值未与后端确认 | 读 `src/config/app.js` + 问后端 |
| 8 | 守卫 busy 去重被误判为「没弹框」 | 读 `src/services/http/guard.js` |

**先查 `.claude/memory/bug_history.md` 与 `known_issues.md`** —— 可能已经踩过。
