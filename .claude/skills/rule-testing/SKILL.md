# rule-testing

> ## ⚠️ 第一规则：默认不允许执行测试
> **除非用户在本轮明确要求**（「执行测试」「跑一下」「验证一下」），
> **否则只生成测试代码与用例清单，不运行任何测试命令。**
>
> 同理：不擅自 `npm install`、不擅自引入测试框架、不擅自跑构建。

## 项目现状（决定了测试策略）

| 项 | 现状 |
|---|---|
| 测试框架 | **未安装**（`devDependencies` 无 vitest / jest） |
| 已有测试 | 无 |
| 可自动化 | `src/utils/*` 纯函数 · `services/http/error.js` 的分支 · `defaultPick` / `finished` 判定 |
| 难自动化 | 页面（依赖 uni 运行时）· 请求链路（依赖 `uni.request`，需 mock `transport`）· 多端差异 · 真机签名 |

**结论**：本工程当前以 **用例清单 + 手工验证步骤** 为主，单测为辅。
引入 vitest 是**用户决策**（`.claude/templates/unit-test/` 已备好可用模板）。

**诚实原则**：与其写一堆跑不起来的「测试」，不如给一份能照着做的手工清单。
**覆盖率不是目标，说清盲区才是。**

## 覆盖优先级（按投入产出排序）

1. ★★★ **纯函数** —— `src/utils/*`（`qs` / `date` / `color` / `number` / `text` / `threshold`）。
   零依赖、零 mock，最高性价比。**优先写这些。**
2. ★★★ **错误归一** —— `services/http/error.js` 的 `toApiError` / `errorTip`，每个 `type` 一条。
3. ★★ **分页容错** —— `composables/useList.js` 的 `defaultPick`（`list`/`data`/`rows` 容错）
   与 `finished` 判定（无 `total` 时靠「不足一页」）。
4. ★★ **边界** —— `maskMobile` 的长度边界（分界点是 **7**）；
   `buildURL` 的数组参数展开与空值过滤（**保留 `0` / `''` / `false`**，只滤 `undefined`/`null`）。
5. ★ **状态机** —— `usePullRefresh` 三段态（需 mock 生命周期，成本较高）。
6. **回归** —— `.claude/memory/bug_history.md` 里每一条。
7. **手工清单** —— 真机登录、签名、下拉跟手、弹窗队列、多端样式隔离。

❌ **不写 E2E**（本工程无此基础设施，写了也跑不起来）。

## 用例 design 规则

- **一用例一断言主题**。
- **名字说清「在什么输入下期望什么」**：
  ```js
  // ❌ it('works', ...)
  // ✅ it('maskMobile：长度 <7 时全星号（不猜格式）', ...)
  ```
- **必测边界**：空值 / `null` / `undefined` / `0` / 空数组 / 超长 / 非法类型。
- **必测失败路径**：`ApiError` 每个 `type` 都要有用例。
- ❌ **禁止为让测试通过而修改业务代码**（测试适配实现，不是反过来）。
- ❌ **禁止制造假覆盖率**（只测 happy path、`expect(true).toBe(true)`）。
- ❌ **测试里不写真实 token / 手机号 / 密钥**（用 `13800000000`、`token_fake_xxx`）。
- ❌ **测试里不写会打到生产的地址 / 生产凭证** —— 单测一旦被误跑就会写脏生产数据，这个损失不可回滚。
- **mock 数据必须标注来源**（契约文档 / 真实响应录制 / 手工编造）；编造的必须标「**结构待契约确认**」——
  不标就会变成假契约，后续开发照着它写接口。
- ❌ **断言不得依赖 `VITE_MOCK_LOGIN_CODE` 的登录结果** —— 该通道只在 local / develop 生效、生产无效，
  靠它得到的「通过」是假的。

## ★ 必须覆盖的手工验证清单（本工程特有）

| # | 项 | 验证内容 | 为何不能自动化 |
|---|---|---|---|
| 1 | **登录链路** | 微信静默登录换 `token` / `admin_info` / `permission`；**未绑定**（`58001`）是否稳定落到绑定页；绑定成功**不再调登录接口**（响应结构相同） | 依赖 `wx.login` 真机能力；⚠️ **H5/开发者工具复现不出未绑定分支**（非微信端走 `VITE_MOCK_LOGIN_CODE`，永远登得上） |
| 2 | **签名** | header 7 个字段齐全；`sign` 为大写 MD5 | 依赖运行时 `apiKey` 与后端校验 |
| 3 | **重登重放** | 手工制造 `40005`，确认自动重登且**只重放一次** | 需后端配合造数据 |
| 4 | **守卫去重** | 并发 10 个请求同回 `50008`（账号禁用）或 `58004`（未配角色），确认**只弹一个框** | 需后端配合 + 并发时序（本工程只登记了这两枚守卫码） |
| 5 | **守卫冷静期** | 框未关前不重复弹、不提前放行 | 同上 |
| 6 | **环境口径** | `grep localhost:15000 dist/` 确认为空 | 需真实构建产物 |
| 7 | **弹层（MP 端）** | `.u-popup` / `.u-datetime-picker` 是否仍被页面滚动区挤压 | ⚠️ **仅 H5 语义下验过，MP 端未确证**（K-08） |
| 12 | **冷启动启动态** | 未绑定微信冷启动：「整屏极光 + 品牌卡」→ 绑定页的**视觉连续性**；`reLaunch` 中间帧是否闪白；**已绑定微信是否一次都看不到启动态** | ⚠️ **H5 / 开发者工具复现不出这一屏**（非微信端走 mock code）→ 必须真机 + 未绑定微信号（K-21） |
| 13 | **静态：全局浮层位置** | 每页的 `<app-loading>` / `<app-modal>` 是否在 `v-if` / `v-else` **之外**（拆首屏态时最容易拆掉它们，见 BUG-012） | ✅ 可静态检查 |
| 8 | **下拉跟手** | 三段态在 MP 与 H5 表现一致 | 真机手势 |
| 9 | **安全区** | `$safe-bottom` / `$safe-top` 在刘海屏/全面屏正常 | 需真机机型 |
| 10 | **存储隔离** | H5 同域下与 C 端不串登录态 | 需两工程同域部署 |
| 11 | **tabBar 跳转** | 若启用 tabBar，`route.to` 是否正确（依赖 `TAB_PAGES` 同步） | 需真机 |

⚠️ **未确证项必须标「未确证 / 需真机验证」，不得写成「已通过」。**

## 产出必须包含这三部分

1. **测试文件**（完整内容，中文 why 注释）
2. **用例清单表**：`用例名 · 输入 · 期望 · 覆盖点 · 可自动化?`
3. ★ **未覆盖清单 + 原因** —— 这部分**不可省**。它比覆盖率数字更有价值。

外加：**执行命令**（供用户自行执行，不是你去跑）+ **未确证项标注**。

| 栈 | 框架 | 命令（★ 需用户授权） |

## 硬性禁令（MUST / MUST NOT）

> **本节是本主题 MUST / MUST NOT 的唯一权威。**

1. ❌ **未经用户明确要求就执行测试**
2. ❌ 擅自安装测试框架 / 依赖
3. ❌ 为让测试通过而改业务代码
4. ❌ 制造假覆盖率
5. ❌ 编造测试结果（没跑却说通过）
6. ❌ 测试里写真实敏感数据
7. ❌ 把「未确证」当「已通过」
8. ❌ 写 E2E
9. ❌ 测试里写会打到生产的地址 / 生产凭证（误跑即写脏生产，不可回滚）
10. ❌ mock 数据不标来源（编造的必须标「结构待契约确认」）
11. ❌ 断言依赖 `VITE_MOCK_LOGIN_CODE`（生产无效，靠它得到的「通过」是假的）

## 登记义务

- 每个 **bugfix** 流程**必须**产出回归用例，并登记 `.claude/memory/bug_history.md`
  （现象 / 根因 / 修复 / **防复发措施**）。
- 无法自动化的回归项 → 写进手工清单，**必须**标注「未确证 / 需真机验证」。
