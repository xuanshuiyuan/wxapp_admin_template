# design-preview

把「一句话需求」或「一张界面图」变成 `docs/design/` 下可预览的 HTML 模板。
本 skill **只产出设计稿**，不改 `src/` 业务代码；要写真实页面请走 `rule-add-page` + `project-dev`。

## 0. 先读最新（不可跳过）

1. 打开 `docs/design/00-LATEST.md`：拿「最近一次模板」、按任务类型的**参考锚点**、当前清单。
2. 打开对应锚点 HTML，**照它的 `<head>` / CSS 变量 / 结构写**。不要凭印象、不要遍历目录猜。
3. 读 `references/design-system.md`（本 skill 附带的 token 与骨架摘要）。
4. 冲突时优先级：**最新模板文件 > 本 skill 摘要 > 记忆**。

> 为什么必须先读：设计稿目录按功能分（auth / home / <domain>），
> 文件名看不出先后；`00-LATEST.md` 是唯一维护「最新 + 锚点」的地方。
> 跳过它就会照着旧稿写，这是本 skill 最需要防的失败模式。

## 1. 把输入变成页面清单

### 文字需求
先在心里（或回复里）列出：**页面类型**（首屏 / 列表 / 详情 / 表单 / 搜索 / 弹层 / 权限树）、
使用场景、区块顺序、字段或列、操作按钮、状态（空 / 错 / 禁用 / 部分选中）、底部动作。

### 文字需求来自 design-brief

如果输入是本仓之外的 `design-brief.md`（页面清单 / 字段口径 / 状态档 / 动作），
按它出稿；跨 WSL / Windows 时注意路径写法（UNC 与 Linux 路径不能混用，读不到先换写法，
别猜文件不存在）。下面按 brief 出：

- 按它第 1 节的页面清单和逐页的「区块顺序 / 字段与口径 / 状态档 / 动作与出口」出稿，
  **不自己重排信息架构**；brief 没写的区块不要加。
- 「契约状态 = 无契约」的字段一律标「示意名」；brief 里出现字段名 ≠ 已经定契约。
- 出稿后把「待后端确认」回灌到**来源 brief / open-questions 的待确认区**，
  **不要只留在稿头**——稿是前端视图，契约的拍板真源在后端那份文档。
- brief 与本项目锚点的页面结构冲突时：**页面结构以本项目最新锚点为准，业务字段以 brief 为准**，
  冲突项进待确认，不在稿里自行取舍。

### 图片
- **只提取信息结构**：区块、字段、操作、层级、重点；**不照搬**配色、字体、圆角、阴影。
  用本项目既有视觉语言重绘 —— 项目要的是"这套语言下的新页面"，不是外来截图复刻。
- 如果图片本身就是本项目稿（Aurora Glass），沿用其视觉，只补新内容。
- 如果用户明确说"一比一复刻"，先确认一句：是**复刻布局**，还是连**视觉风格**一起换。
  后者属于新视觉方向，要改目录与索引，不是本 skill 的默认路径。

### 缺信息怎么办
- 只问**会改变布局**的 1–3 个问题（例如：列表还是表单？有没有底部主操作？）。
- 其余按常识默认，并在稿里用**示意数据**；交付时明确说"这些是示意，不是契约"。
- **不编造后端字段名、权限码、错误码**。需要时写 `PERM_XXX` 这种明显占位，
  并在交付说明里列「待确认」。

## 2. 选目录与文件名

现有功能域（按你的项目实际目录调整；新项目只有模板自带的生成脚本，没有业务稿）：

```
docs/design/<style-name>/
├── auth/     登录 / 绑定等品牌页
├── home/     首页 / 工作台
└── <domain>/ 其他业务域（kebab-case）
```

- 新页面优先落到**已有功能域**；新功能域就新建 `kebab-case` 目录。
- 文件名 `kebab-case`，**一页一模板**：一个 HTML 只放一张稿；
  弹层打开态、空态、错误态如果值得单独看，就各建一张，不要塞进同一页。
- 不建 `index/` 包装层；总览统一用 `docs/design/index.html`。

## 3. 画稿

### 两种页面口径（先选对）

| 口径 | 适用 | 特征 |
|---|---|---|
| **首屏 / 品牌页** | 首页、绑定页、登录类 | 极光渐变底 + 玻璃卡 + 白字；`navigationBarTextStyle: "white"` |
| **二级页** | 列表 / 详情 / 表单 / 搜索 / 设置 | 白色自绘顶栏 + `#FAFAFE` 浅底 + 白卡 + 紫为唯一强调色；**不上极光、不上玻璃** |

### 硬约束（稿子必须满足）

- 画布 **390×844**；外层舞台 540×1060，手机框圆角 44px，内部可滚动。
- **自包含**：不引外网字体、图标库、远程图片；图标一律**内联 SVG**（`currentColor`）。
- 一页一模板；顶部只有一行 `stage-title`，**稿子旁边不放设计论述**。
- 底部固定动作栏要留安全区（稿内固定 20px 代表，落地才用 `$safe-bottom`）。
- 微信胶囊占位 **87×32 那一块不放动作按钮**；自绘顶栏要给它让位。
- 整格是 `<a>` 的入口/行，CSS 里记得 `text-decoration: none`（否则副说明带下划线）。
- 手机号脱敏（`138****8388`）；token / 密钥不出现。
- 中文注释**解释 why**：为什么这个间距、为什么这个状态置灰、为什么这里不用极光。
- 所有数字/人名/单号都是**示意数据**；不要在稿里假装是接口契约。

### 视觉值
- 只从 `references/design-system.md` 与锚点文件里取值；
  **不要新造色值、字号、圆角**。确实需要新档时，先说明理由，并登记到交付说明。
- 设计稿只影响 `docs/design/`，不改 `src/` 的真实样式 token。

## 4. 自检（必须做）

生成后先跑截图，再**真的看图**：

```bash
bash .claude/skills/design-preview/scripts/render.sh <你生成的.html>
```

然后用 Read 打开输出的 PNG，逐项检查：

- 文字溢出 / 截断 / 换行是否合理（长角色名、长权限码、长单号）。
- 底部固定栏是否遮住最后一张卡（内容区要留出约 104px）。
- 顶栏返回/标题/胶囊占位是否挤在一起。
- 有没有意外的下划线（`<a>`）、默认蓝色链接、外链图标。
- 手机框内是否出现横向滚动。
- 空态/禁用态是否真的“看起来不可点”，而不是只改了个字。

发现问题就改，改完**重新渲染再看一眼**；不要把没看过的稿子交给用户。

## 5. 更新索引（必做，不是可选）

新建 / 改名 / 移动模板后，同步这几处：

1. `docs/design/00-LATEST.md`
   - 更新「最近一次模板」的日期与模块；
   - 把新稿加进「直接参考」表（按任务类型给锚点）；
   - 旧稿保留就标「参考」。
2. `docs/design/latest.html`
   - ★ **只放「最新一次要求做的页面」**（用户 2026-11-13 定版）：每次有新需求就**整页替换**，
     只保留这一批稿子的 `frames`；
   - **不保留**「上一版 / 同版增补 / AI 实现说明」分组 —— 历史稿只维护在 `index.html`
     与 `00-LATEST.md` 的清单里；
   - 它只是视图，模板真相源仍在 `c-aurora-glass/` 下。
3. `docs/design/README.md`
   - 「当前模板」表加一行（功能 / 文件 / 状态 / 更新日期）；
   - 「更新记录」追加一条（日期 + 做了什么）。
4. `docs/design/index.html`
   - 新功能域或重要页面，加进对应分组的画廊（iframe + 一行图注）。

> 不更新索引 = 下次 AI 会照着旧稿写。这条比稿子本身更重要。

## 6. 交付给用户

回复里给：

- **文件路径**（可点击）与预览方式（双击 / `index.html` / `latest.html`）。
- 一句话说明这页的关键结构（例如「列表卡 + 底部新增」）。
- **哪些是示意数据**（人名、单号、权限码、数量）。
- **待确认项**（后端字段、权限码、状态机）—— 没有就写「无」。
- **回灌**：输入来自后端 design-brief 时，待确认项必须已写进后端 `versions/vN/open-questions.md` G 区（给 G 编号，路径写法同上表）；没写就直说没写。
- 没画的边界（空态 / 错误态 / 二次确认等），避免用户以为已经覆盖。

## 不要做

- 不要改 `src/`、`pages.json`、`config/`（设计稿 ≠ 实现）。
- 不要手改 `src/uni_modules/`。
- 不要外链字体/图标/图片，不要把大图打进稿子。
- 不要在一页里塞多个模板或多个状态（一页一模板）。
- 不要编造接口/权限码；不确定就标「待确认」。
- 不要把「设计说明」写进稿子 —— 说明进模块 `README.md` 或交付回复。
