# 架构成因（为什么这样分层）

> 规则正文在 `skills/rule-layering` / `rule-request-chain` / `rule-session-guards`。
> 本文件只记「为什么这么设计」，避免后人按通行做法「优化」掉这些非显然的约束。

## 1. 为什么 http 层不认识 session

`request.js` 只认识「谁来处理登录失效」，由 `session.js` 在模块加载时
`registerAuthHandler(relogin)` 注册。直接 import 会形成
`http → session → http` 循环依赖（session 要发登录请求）。
**代价**：`main.js` 有一条不可删的副作用 import；删掉后 40005 不再自动重登。

## 2. 为什么 40005 要「单飞」重登 + 只重放一次

并发 5 个请求同时回 40005，若各登各的会产生 5 次 wx.login、5 个新 token（互相作废）。
`session.login()` 用 pending Promise 单飞；重放只做一次，杜绝「40005 → 登录 → 又 40005」死循环。

## 3. 为什么登录/绑定必须 `authRetry:false`

登录接口自己回 40005 时若又触发重登，就是递归。请求层的「补会话」逻辑同理必须跳过。

## 4. 为什么权限判定有两处（配置 + 服务端）

前端按登录下发的 `permission` 做显隐 / 准入（体验层），服务端按登录缓存里的
「角色授权路径列表」逐路径校验（真防线）。前端判据是**登录快照**，最长 2h 才刷新，
不能当「一定调得通」的凭据 —— 所以页面必须处理 `40102`。

## 5. 为什么入口清单放本地配置而不是接口下发

后端加模块时老版本小程序要能「不白屏」：本地清单是已知集合，认不出的模块直接跳过。
接口只下发数量，不下发清单 / 图标 / 按钮 —— 那些是产品文案，不该由接口决定。

## 6. 为什么 loading 要 200ms 延迟 + 300ms 最短停留

快请求转圈只闪一帧，观感像页面抖；已经转出来的圈一闪而过比不转更困惑。
两个值都在 `config/app.js`，改它们影响全项目所有 `{ loading:true }`。

## 7. 为什么「跳页取值」而不是页内弹层

键盘弹层在各机型遮挡与高度表现不一；整页承载控件最稳，也不与列表抢高度。
机制收在 `services/pickPage.js`（Promise + 全局事件 + 在飞去重 + 跳转失败释放监听）。
