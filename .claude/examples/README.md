# examples/ — 端到端示例

> **用途**：把整套系统**跑一遍给人看**。
> 规则文档告诉你「该怎么做」，示例告诉你「做出来长什么样」。

## 文件

| 文件 | 内容 |
|---|---|
| `feature-walkthrough.md` | **完整 feature 流程示例** —— 从需求到评审通过的全部产物 |

## 为什么需要示例

这套系统有十余个目录、几十个文件。新人（或新会话的 AI）读完规则后，
**仍可能不知道「一个阶段的实际产出该有多少细节」**。

示例回答三个具体问题：

1. **每个 agent 的输出到底长什么样？**（多长？多细？什么格式？）
2. **闸门（gate）不通过时怎么退回？**（什么算 blocker？）
3. **一次改动最后要留哪些记录？**（CHANGELOG 条目、memory 更新长什么样）

## ⚠️ 示例的诚实声明

**示例中的后端契约是虚构的**（「演示记录列表」接口在本模板中不存在，
契约待接后端后确定，见 `memory/known_issues.md`）。

虚构是刻意的，理由：
- 若用真实契约，示例会随契约变化而过期；
- 虚构的契约能完整展示「契约表该有哪些字段」这一形态。

**示例中标注为「本项目真实事实」的部分**（目录结构、红线、页壳必需件、
`useList` 契约、`options` 默认值等）**都是真的**，可直接照用。

## 阅读建议

| 你是谁 | 读法 |
|---|---|
| **第一次用这套系统** | 通读 `feature-walkthrough.md`，重点看「阶段 1」「阶段 6」「阶段 8」 |
| **想知道怎么调用 agent** | 看示例里的「主对话说了什么」引用块 |
| **想知道输出要多细** | 对比示例里各阶段的产物长度 |
| **想知道闸门怎么拦** | 看示例末尾的「闸门拦截示例」 |
| **已经在用了** | 当模板抄 —— 复制示例里的格式 |

## 其它示例类型（暂缺，按需补）

| 类型 | 何时补 |
|---|---|
| `bugfix-walkthrough.md` | 遇到第一个有代表性的真机 bug 后 |
| `refactor-walkthrough.md` | 做第一次真实重构后 |
| `release-walkthrough.md` | 第一次真实发布后 |

> **原则**：示例应当是**真实发生过的**（脱敏后），而不是编的。
> 编的示例会教出错误的细节。本次只写了 feature 示例，因为其余类型尚无真实案例 ——
> **不编造**（与全系统的诚实原则一致）。
